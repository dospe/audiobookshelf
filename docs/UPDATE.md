# Installing and updating the Audiobookshelf server (`dospe` fork) in `/opt/audio`

This guide describes how to deploy and maintain the whole server stack with
the two scripts in `scripts/`:

| Script | Purpose |
| --- | --- |
| `deploy.sh` | First installation or re-deployment: creates `/opt/audio`, takes over the data of an old installation, writes the configuration and starts the stack. Has a remote mode over SSH. |
| `update-server.sh` | Routine idempotent update: pulls new images, backs up the config, recreates only the containers whose image changed, verifies the health checks. Suitable for cron. |

The stack consists of up to four services in one Docker Compose project:

| Service | Image | Host port | Note |
| --- | --- | --- | --- |
| `audiobookshelf` | `ghcr.io/dospe/audiobookshelf` (this fork) | `ABS_PORT`, default 13378 | web UI and API |
| `provider` | `ghcr.io/stecik/audiobookshelf_czech_metadata` | `PROVIDER_PORT`, default 8000 | Czech metadata provider; Audiobookshelf calls it inside the compose network as `http://provider:8000` |
| `caddy` | `caddy:2` | 80 and 443 (`CADDY_HTTP_PORT`, `CADDY_HTTPS_PORT`) | HTTPS reverse proxy for `CADDY_DOMAIN` with an automatic Let's Encrypt certificate; deployed only when a domain is set |
| `rclone` | `rclone/rclone` | none | FUSE mount of a cloud remote (`RCLONE_REMOTE`, e.g. Google Drive) at `RCLONE_MOUNT_POINT`; Audiobookshelf sees it as `/media`; deployed only when a remote is set |

All images are public; no registry login is needed on the server.

## Layout of `/opt/audio`

| Path | Content |
| --- | --- |
| `/opt/audio/.env` | the single configuration file of all services; created by `deploy.sh`, edited by hand afterwards and never overwritten |
| `/opt/audio/docker-compose.yml` | generated by `update-server.sh`, do not edit by hand |
| `/opt/audio/deploy.sh`, `/opt/audio/update-server.sh` | copies of the scripts installed by `deploy.sh` |
| `/opt/audio/config` | Audiobookshelf database and settings (back this up) |
| `/opt/audio/metadata` | covers, cache, streams (can be regenerated) |
| `/opt/audio/backups` | config backups made by updates (`config-<date>.tar.gz`) |
| `/opt/audio/audiobooks` | the library, unless `.env` points elsewhere (`ABS_AUDIOBOOKS_DIR`) |
| `/opt/audio/caddy/Caddyfile` | configuration of the HTTPS proxy; created at deployment (taken over from the old installation or generated from `--domain`), edited by hand afterwards and never overwritten |
| `/opt/audio/caddy/data` | Let's Encrypt certificates and account (back up together with the config; when lost Caddy requests new ones) |
| `/opt/audio/caddy/config` | internal Caddy state |
| `/opt/audio/rclone/config/rclone.conf` | credentials of the cloud remote (created by `rclone config`, taken over on migration; back it up, it contains a token) |
| `/opt/audio/rclone/cache` | rclone VFS cache (up to `--vfs-cache-max-size`, may still hold files not yet uploaded; moved, not copied, on migration) |
| `/opt/audio/.update.lock` | lock against concurrent updates |

## Requirements

- Linux with Docker 20.10+ and the Docker Compose v2 plugin (`docker compose version`).
- `curl`, `tar`, `flock` (package `util-linux`), optionally `rsync` for a faster data migration.
- Root or `sudo` (the scripts write to `/opt/audio`; `deploy.sh` re-runs itself through `sudo`).
- Network access to `ghcr.io` and `docker.io` (Caddy image).
- For HTTPS: the DNS record of the domain points at the server and ports 80 and 443 are reachable from the outside (Let's Encrypt validates over HTTP on port 80). Nothing else may listen on those ports (another Caddy, nginx, Apache).
- For rclone: a kernel with FUSE (`/dev/fuse`) and a mount point on a shared mount (the systemd default has `/` as `shared`; otherwise `mount --make-rshared /`).

The scripts live in the public repository `dospe/audiobookshelf`, so you can
copy them to the server with `scp` from a clone or download them with `curl`.
The simplest way is the remote mode `deploy.sh --remote`, which transfers both
scripts by itself.

## First installation

### Option A: remotely from a computer with a clone of the repository

```bash
cd audiobookshelf/scripts
./deploy.sh --remote user@audio.example.com
```

The script copies `deploy.sh` and `update-server.sh` over `scp`, runs
`deploy.sh` on the server (through `sudo` unless you are root) and prints a
summary when done. All options below can be passed in remote mode too, for
example `./deploy.sh --remote user@host --audiobooks /mnt/books --port 13378`.

### Option B: directly on the server

```bash
sudo mkdir -p /opt/audio
# copy both scripts to /opt/audio (scp) or download them:
for f in deploy.sh update-server.sh; do
  sudo curl -fsSL \
    "https://raw.githubusercontent.com/dospe/audiobookshelf/master/scripts/$f" \
    -o "/opt/audio/$f"
done
sudo chmod +x /opt/audio/*.sh
sudo /opt/audio/deploy.sh
```

### What `deploy.sh` does

1. Checks `docker`, `docker compose`, `curl` and installs both scripts into `/opt/audio`.
2. **Migration** (only when `.env` does not exist yet and `--no-migrate` is not given):
   - finds an existing `audiobookshelf` container (from `docker run` or from
     another compose project), reads its `/audiobooks`, `/config` and
     `/metadata` mounts; the library path goes into `.env`, the content of
     `config` and `metadata` is copied into `/opt/audio` (from a bind mount
     as well as from a named volume through `docker cp`), the container is
     stopped and removed (volumes are not deleted);
   - without a container it tries the old layout `/opt/audiobookshelf/{config,metadata}`;
   - finds the old provider deployment of the original `deploy.sh` in
     `~/abs-czech-metadata` (in the home directory of the user and of root),
     takes over its `.env` (`HOST_PORT` → `PROVIDER_PORT`, token, `ENABLE_*` …),
     stops the old compose project and renames its directory to
     `abs-czech-metadata.migrated-<date>`;
   - from the old `audiobookshelf` container it also takes over the **other
     bind mounts** (`/media` → `ABS_MEDIA_DIR`, anything else → `ABS_EXTRA_MOUNTS`
     including `ro` and propagation) and the user it ran as (`ABS_UID`/`ABS_GID`);
   - finds an old rclone container (named `rclone*` or using the image
     `rclone/rclone`) from another compose project, reads the remote and the
     mount options from its command, the server user's UID/GID from the old
     `.env`, copies `rclone.conf`, **moves** the VFS cache (it may hold files
     not yet uploaded), removes the container and recreates the mount in the
     new stack. This step also runs on an existing `/opt/audio` installation
     whose `.env` has no `RCLONE_*` section yet;
   - finds an old Caddy container (named `caddy` or using the image `caddy:*`)
     from another compose project, reads the domain and the Let's Encrypt
     e-mail from its Caddyfile, copies the Caddyfile and the certificates
     (`/data`, `/config`; from a bind mount as well as from a named volume) into
     `/opt/audio/caddy`, removes the container and, when no container is left
     in the old compose project, renames its directory to
     `<name>.migrated-<date>`. This step also runs on an existing `/opt/audio`
     installation whose `.env` has no `CADDY_*` section yet.
3. Writes `/opt/audio/.env` (defaults + detected paths + imported provider
   values + Caddy domain + rclone remote + user). On later runs `.env` is kept
   and only the command line options are applied to it.
4. Runs `update-server.sh --force`: writes the compose file, creates a missing
   `caddy/Caddyfile`, changes the ownership of `config` and `metadata` when
   `ABS_UID` is set, pulls the images, creates the containers and waits for
   `/healthcheck` (Audiobookshelf), `/health` (provider) and the health checks
   of Caddy and rclone (the mount exists).

Data is copied only into an empty target directory; existing content of
`/opt/audio/config`, `/opt/audio/caddy/Caddyfile` and `/opt/audio/caddy/data`
is never overwritten.

### `deploy.sh` options

| Option | Meaning |
| --- | --- |
| `--remote user@host` | Transfers the scripts over SSH and runs the deployment on the server. |
| `--dir DIR` | A deployment directory other than `/opt/audio`. |
| `--audiobooks PATH` | Host path of the library (otherwise from the migration, otherwise `DIR/audiobooks`). |
| `--port N` | Audiobookshelf port (default 13378). |
| `--provider-port N` | Provider port (default 8000). |
| `--domain HOST` | Public domain for HTTPS (`CADDY_DOMAIN`, enables `CADDY_ENABLED=true`). Without it the domain is taken from the old Caddyfile; when none is known, Caddy is not deployed. |
| `--email ADDRESS` | Contact e-mail for Let's Encrypt (`CADDY_EMAIL`; otherwise from the old Caddyfile). |
| `--rclone-remote R` | Remote to mount, e.g. `gdrive:Audiobookshelf` (`RCLONE_REMOTE`, enables `RCLONE_ENABLED=true`). Without it the remote is taken from the old rclone container; when none is known, rclone is not deployed. |
| `--mount-point PATH` | Mount point on the host (`RCLONE_MOUNT_POINT`, default `/mnt/gdrive` or the old one). |
| `--media-dir PATH` | Host directory shown in Audiobookshelf as `/media` (`ABS_MEDIA_DIR`; default the rclone mount point, or the `/media` of the old container). |
| `--user UID:GID` | User Audiobookshelf runs as (`ABS_UID`/`ABS_GID`; default from the old container or the old `.env`, otherwise root). |
| `--tag TAG`, `--provider-tag TAG`, `--caddy-tag TAG`, `--rclone-tag TAG` | Image tags (defaults `latest`, `latest`, `2`, `latest`). |
| `--no-provider` | Do not deploy the provider (`PROVIDER_ENABLED=false`). |
| `--no-caddy` | Do not deploy Caddy (`CADDY_ENABLED=false`); an old Caddy container is then only stopped. |
| `--no-rclone` | Do not deploy rclone (`RCLONE_ENABLED=false`); an old rclone container keeps running. |
| `--no-migrate` | Do not look for an old installation. |

### After the installation

1. Open `https://<domain>/` (with Caddy) or `http://<server>:13378/`. After a
   migration log in with the original accounts; on a clean installation go
   through the setup wizard.
2. Inside the container the library path is `/audiobooks` and the cloud
   storage mounted by rclone is `/media` (e.g. `/media/Audiobooks`,
   `/media/Ebooks`); on a clean installation create the libraries in
   Audiobookshelf with these paths. After a migration run a library scan;
   items marked as Missing come back.
3. Add the provider in Audiobookshelf: Settings → Metadata Tools → Custom
   Metadata Providers → Add, Media Type `Book`, URL `http://provider:8000`.
   Fill in the Authorization header only when `AUDIOBOOKSHELF_AUTH_TOKEN` is
   set in `.env`. For individual sources you can add more providers with the
   URL `http://provider:8000/<source>` (e.g. `/audioteka`).
4. Run a library scan so that `.doc`, `.docx`, `.rtf` and `.pdb` files are
   registered as ebooks. Folders holding several ebooks are split into one
   book per file; see [EBOOKS.md](EBOOKS.md).

## `.env` configuration

```dotenv
# --- Audiobookshelf server (fork image) ---
ABS_IMAGE=ghcr.io/dospe/audiobookshelf
ABS_TAG=latest                      # edge, a fork version (e.g. 2.36.0-dospe.3), or latest@sha256:<digest>
ABS_PORT=13378
ABS_AUDIOBOOKS_DIR=/opt/audio/audiobooks
ABS_CONFIG_DIR=/opt/audio/config
ABS_METADATA_DIR=/opt/audio/metadata
ABS_BACKUP_DIR=/opt/audio/backups
ABS_BACKUP_KEEP=7
ABS_TZ=Europe/Prague
CUSTOM_METADATA_PROVIDER_TIMEOUT=30000   # ms; how long Audiobookshelf waits for a custom provider response

# --- Czech metadata provider ---
PROVIDER_ENABLED=true
PROVIDER_IMAGE=ghcr.io/stecik/audiobookshelf_czech_metadata
PROVIDER_TAG=latest
PROVIDER_PORT=8000
LOG_LEVEL=INFO
REQUEST_TIMEOUT_SECONDS=5
SCRAPER_TIMEOUT_SECONDS=5
AUDIOBOOKSHELF_AUTH_TOKEN=
SCRAPER_USER_AGENT=
ENABLE_ALZA=true
# ... ENABLE_<source>=true/false for every shop, ENABLE_DATABAZEKNIH=false

# --- Storage and user of the Audiobookshelf container ---
ABS_UID=1001                        # empty = root; config and metadata are chowned to this user
ABS_GID=1001
ABS_MEDIA_DIR=/mnt/gdrive           # host directory shown as /media (rslave propagation); empty = no mount
ABS_EXTRA_MOUNTS="/srv/books:/mnt/books:ro"   # extra bind mounts host:container[:ro][:rslave], space separated

# --- rclone: FUSE mount of a cloud remote ---
RCLONE_ENABLED=true
RCLONE_IMAGE=rclone/rclone
RCLONE_TAG=latest
RCLONE_REMOTE=gdrive:Audiobookshelf # remote:path from rclone.conf; empty = rclone is not deployed
RCLONE_MOUNT_POINT=/mnt/gdrive
RCLONE_CONFIG_DIR=/opt/audio/rclone/config
RCLONE_CACHE_DIR=/opt/audio/rclone/cache
RCLONE_MOUNT_ARGS="--allow-other --allow-non-empty --umask 002 --vfs-cache-mode full --vfs-cache-max-size 2G --vfs-cache-max-age 720h --vfs-read-ahead 64M --buffer-size 16M --dir-cache-time 72h --poll-interval 1m --log-level INFO"

# --- Caddy: HTTPS reverse proxy (Let's Encrypt) ---
CADDY_ENABLED=true                  # false = Caddy is not deployed (the container is removed as an orphan)
CADDY_DOMAIN=audio.example.com      # public domain; required when CADDY_ENABLED=true
CADDY_EMAIL=admin@example.com       # Let's Encrypt contact (optional)
CADDY_IMAGE=caddy
CADDY_TAG=2
CADDY_HTTP_PORT=80
CADDY_HTTPS_PORT=443
```

Changed values in `.env` take effect on the next run of `update-server.sh`
(compose notices changed ports and paths and recreates the container); to be
sure run `update-server.sh --force`.

## Storage through rclone

The `rclone` service mounts `RCLONE_REMOTE` through FUSE at
`RCLONE_MOUNT_POINT` (inside the container `/data` with `shared` propagation).
Audiobookshelf has the same directory as `/media` with `rslave` propagation, so
the mount stays visible even after rclone restarts. The container runs with
`/dev/fuse`, `SYS_ADMIN` and the AppArmor profile disabled, as FUSE in Docker
requires.

Create a new remote (without a migration) interactively:

```bash
sudo docker run --rm -it -v /opt/audio/rclone/config:/config/rclone rclone/rclone config
```

For Google Drive: `n` → name `gdrive` → type `drive` → your own `client_id` and
`client_secret` (recommended, otherwise you share the API quota) → scope `1` →
"Use web browser" **No** → run the `rclone authorize` command on a computer
with a browser and paste the token back. Then put `RCLONE_REMOTE=gdrive:<folder>`
and `RCLONE_ENABLED=true` into `.env` and run `update-server.sh --force`.

The mount options are in `RCLONE_MOUNT_ARGS` (the remote, the mount point and
`--cache-dir` are added by the script). The `--vfs-cache-mode full` cache holds
up to `--vfs-cache-max-size` in `/opt/audio/rclone/cache`; files uploaded
through Audiobookshelf are sent to the cloud in the background, which is why
the cache is moved on migration and never deleted.

For libraries under `/media` enable **Disable folder watcher** in
Audiobookshelf (inotify does not work on FUSE) and a **scheduled scan** (e.g.
`0 4 * * *`); changes made on Drive show up in the mount within
`--poll-interval`.

## HTTPS through Caddy

Caddy runs as the `caddy` service in the same compose project, so it reaches
Audiobookshelf inside the network as `audiobookshelf:80`. It requests the
certificate for `CADDY_DOMAIN` itself on the first start (HTTP-01 on port 80)
and renews it automatically; the certificates and the Let's Encrypt account are
in `/opt/audio/caddy/data`, which is why they are copied on migration and not
issued again.

Default `/opt/audio/caddy/Caddyfile`:

```caddyfile
{
	email admin@example.com
}

audio.example.com {
	encode zstd gzip
	reverse_proxy audiobookshelf:80
}
```

The Caddyfile is yours: the scripts create it only when it does not exist.
After editing it by hand reload it without downtime:

```bash
docker exec audiobookshelf-caddy caddy reload --config /etc/caddy/Caddyfile
```

Changing `CADDY_DOMAIN` in `.env` does not change the Caddyfile; edit the
domain in both files (`.env` serves the scripts for output and checks). To
expose the provider over HTTPS as well, add for example this to the domain
block:

```caddyfile
	handle_path /provider/* {
		reverse_proxy provider:8000
	}
```

In Audiobookshelf keep using the internal URL `http://provider:8000`.

An existing `/opt/audio` installation without Caddy gets it by running
`deploy.sh` again (it finds the old `caddy` container and takes it over) or
`deploy.sh --domain <domain> --email <address>` (clean configuration).

## Routine update

```bash
sudo /opt/audio/update-server.sh
```

Typical output when everything is up to date:

```
[...] Deployment directory: /opt/audio
[...] audiobookshelf: image ghcr.io/dospe/audiobookshelf:latest, container running (image 2f1c9a7b3d4e)
[...] provider: image ghcr.io/stecik/audiobookshelf_czech_metadata:latest, container running (image 9c8d7e6f5a4b)
[...] Pulling ghcr.io/dospe/audiobookshelf:latest
[...] Pulling ghcr.io/stecik/audiobookshelf_czech_metadata:latest
[...] Already up to date, nothing to do
```

When a new Audiobookshelf version is available:

```
[...] audiobookshelf: update needed: new image 8a0b1c2d3e4f (running 2f1c9a7b3d4e)
[...] Backing up /opt/audio/config to /opt/audio/backups/config-20260905-060004.tar.gz
[...] Starting: audiobookshelf
[...] Waiting for http://127.0.0.1:13378/healthcheck
[...] audiobookshelf is up
[...] Done. Audiobookshelf: http://<server>:13378/
```

Only the service whose image changed is recreated. The config backup is made
only before an Audiobookshelf update (the provider has no state). During the
update the affected service is unavailable for roughly 10 to 60 seconds.

### `update-server.sh` options

| Option | Meaning |
| --- | --- |
| `--check` | Only compares the digests on ghcr with the local ones; changes nothing. Exit code `0` = up to date, `2` = an update is available (or nothing is installed), `1` = error. |
| `--service audiobookshelf` / `--service provider` / `--service caddy` / `--service rclone` | Updates a single service. |
| `--force` | Recreates the containers even without a new image (e.g. after changing `.env`). |
| `--no-backup` | Skips the config backup. |
| `--tag TAG` | Audiobookshelf tag; saved to `.env` as `ABS_TAG`. |
| `--provider-tag TAG` | Provider tag; saved as `PROVIDER_TAG`. |
| `--caddy-tag TAG` | Caddy tag (default `2`); saved as `CADDY_TAG`. |
| `--rclone-tag TAG` | rclone tag (default `latest`); saved as `RCLONE_TAG`. |
| `--dir DIR` | A different deployment directory. |

## Automatic updates

### cron

```bash
sudo crontab -e
```

```
0 5 * * * /opt/audio/update-server.sh >> /var/log/audiobookshelf-update.log 2>&1
```

### systemd timer

`/etc/systemd/system/audiobookshelf-update.service`:

```ini
[Unit]
Description=Update Audiobookshelf stack
After=docker.service
Requires=docker.service

[Service]
Type=oneshot
ExecStart=/opt/audio/update-server.sh
```

`/etc/systemd/system/audiobookshelf-update.timer`:

```ini
[Unit]
Description=Daily Audiobookshelf update

[Timer]
OnCalendar=*-*-* 05:00:00
RandomizedDelaySec=15m
Persistent=true

[Install]
WantedBy=timers.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now audiobookshelf-update.timer
journalctl -u audiobookshelf-update.service
```

## Rollback

### To a previous image

```bash
docker images --digests ghcr.io/dospe/audiobookshelf
sudo /opt/audio/update-server.sh --tag "latest@sha256:<digest>"
```

The tag is saved to `.env`, so later runs stay on this version; `--tag latest`
returns to rolling updates. The same works for the provider with
`--provider-tag`.

### Restoring the database from a backup

```bash
cd /opt/audio
docker compose stop audiobookshelf
mv /opt/audio/config /opt/audio/config.broken
tar -xzf /opt/audio/backups/config-20260905-060004.tar.gz -C /opt/audio
docker compose start audiobookshelf
```

Restore a backup with the same or an older server version than the one it was
made with; a newer server migrates the database and an older version then
cannot open it.

## Verification

- `http://<server>:13378/healthcheck` returns HTTP 200; so does `http://<server>:8000/health`.
- `https://<domain>/healthcheck` returns HTTP 200 with a valid certificate
  (`curl -sSI https://<domain>/healthcheck`); `docker logs audiobookshelf-caddy`
  shows no `obtaining certificate` errors.
- `docker compose -f /opt/audio/docker-compose.yml ps` shows all services as `healthy`.
- `mount | grep rclone` shows `RCLONE_REMOTE` at `RCLONE_MOUNT_POINT`; `docker exec audiobookshelf ls /media` lists the library folders.
- A metadata search through the provider works in Audiobookshelf (Match on any book).
- `docker compose -f /opt/audio/docker-compose.yml logs --tail 100` shows no errors.

## Troubleshooting

| Symptom | Cause and fix |
| --- | --- |
| `pull failed` / `denied` / `unauthorized` | Network or ghcr.io outage; try again. Should a package ever be switched to private, log in with `docker login ghcr.io` as the user running the script (root for `sudo` and cron) with a `read:packages` token. |
| `curl: (404)` when downloading the scripts | Wrong URL or branch; the repository is public and no token is needed. Alternatively use `scp` or `deploy.sh --remote`. |
| `cannot talk to the Docker daemon` | Docker is not running or you lack permissions; run with `sudo`. |
| `another update-server.sh is already running` | Another instance is running (cron). Wait, or delete `.update.lock` when the process is provably gone. |
| A service does not come up within 120 s | Read the printed log. Most often a port is taken (`ABS_PORT`, `PROVIDER_PORT`) or the permissions of `config`/`metadata` are wrong (`ABS_UID`/`ABS_GID`). |
| The library is empty after a migration | `ABS_CONFIG_DIR` points elsewhere than the original config, or the data was copied into a non-empty directory (the script left it alone). Check `.env` and the content of `/opt/audio/config`. |
| The scan reports `Invalid folder path does not exist "/media/..."`, items are Missing | The container does not see the library folder: `ABS_MEDIA_DIR`/`ABS_EXTRA_MOUNTS` is missing in `.env`, or rclone is not running (`docker logs audiobookshelf-rclone`). Fix `.env`, run `update-server.sh --force` and then a library scan; Missing items come back, do not use "Remove missing". |
| rclone: `path /mnt/gdrive is mounted on / but it is not a shared mount` | The mount point must be on a shared mount: `sudo mount --make-rshared /` (permanently through a systemd unit or `/etc/fstab`) and `update-server.sh --service rclone --force`. |
| rclone: `Transport endpoint is not connected` / `looks like a stale FUSE mount` | A disconnected mount was left behind: `sudo umount -l /mnt/gdrive` and run the script again. |
| `rclone.conf does not exist` | Create the remote with the command in the "Storage through rclone" section, or set `RCLONE_ENABLED=false`. |
| Audiobookshelf cannot reach the provider | The URL in Audiobookshelf must be `http://provider:8000` (the service name in the compose network), not `localhost`. When Audiobookshelf runs outside this compose project, use `http://<server>:8000`. |
| The provider returns empty results | The Audiobookshelf log shows `[CustomMetadataProvider] Search error timeout of Xms exceeded`: the provider did not answer in time. Raise `CUSTOM_METADATA_PROVIDER_TIMEOUT` (ms, default 30000), or lower `REQUEST_TIMEOUT_SECONDS`/`SCRAPER_TIMEOUT_SECONDS` or disable slow sources with `ENABLE_*=false`. The provider timeouts must stay below `CUSTOM_METADATA_PROVIDER_TIMEOUT`. |
| `--check` reports a manifest error | `docker manifest inspect` needs the network; check the connection to ghcr.io. |
| Caddy does not start, the log shows `bind: address already in use` | Something else listens on port 80/443 (an old Caddy from another compose project, nginx). Stop it (`docker ps`, `ss -ltnp`) and run `update-server.sh --service caddy --force`. |
| HTTPS returns 502 or `dial tcp: lookup audiobookshelf` | Caddy is not in the same compose network as Audiobookshelf. This happens when an old Caddy from the original installation is still around: take it over by running `deploy.sh` again, or temporarily `docker network connect audio_default <old container>`. |
| The Caddy log shows `obtaining certificate ... failed` | The domain's DNS does not point at the server, port 80 is not reachable from the outside, or `CADDY_DOMAIN` does not match the Caddyfile. Caddy retries by itself; with repeated failures mind the Let's Encrypt rate limits (5 issuances per week per domain). |
| `CADDY_ENABLED=true but CADDY_DOMAIN is empty` | Fill in `CADDY_DOMAIN` in `.env` (and the domain in `caddy/Caddyfile`), or set `CADDY_ENABLED=false`. |
